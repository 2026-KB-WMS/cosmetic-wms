## 1. 프로젝트 개요 및 액터 정의

### 1.1. 도메인 특성

화장품은 유통기한과 보관 온도(15~25℃)에 민감하며, 품질 이슈 발생 시 로트(LOT) 단위의 신속한 추적이 필수적이다.

### 1.2. 주요 액터 정의 및 권한 매핑

| 액터명 | 코드값 (Enum) | 비고 |
|--------|--------------|------|
| 총괄 관리자 | `ROLE_HEADQUARTERS` | 본사 관리자. 전사 재고 이동 및 리콜 명령, 시스템 정책 설정 등 시스템 전체 권한 |
| 창고 관리자 | `ROLE_WAREHOUSE_MANAGER` | 입출고 검수, 창고 내 로케이션 관리, 담당 창고의 재고 및 입/출고 처리 권한 |
| 점주 | `ROLE_FRANCHISE_MANAGER` | 가맹점주. 발주, 반품 및 매장 내 유통기한 경과 상품 폐기 신청 권한 |

## 2. 표준 식별 체계 및 로트 관리

### 2.1. 재고 식별 체계

| 구분 | 설명 | 구조 | 예시 |
|------|------|------|------|
| SKU 코드 | 상품 고유 데이터 코드 | `[브랜드]-[카테고리(3)]-[타입(3)]-[용량]-[일련번호(4)]` | `DIO-SKN-SER-150-0001` |
| 로트 번호 | 재고 관리의 실질적 핵심 단위. 동일 제조 공정/일자 묶음 | `[PRD(3)]-[YYMMDD(6)]-[VV(2)]-[SSSS(4)]` | `SKN-260507-01-0024` |
| 섹션 코드 | 재고가 보관된 창고 내 물리적 위치 | `[창고ID(4자리)]-[구역타입코드(4자리)]-[온도코드(1자리)]-[순번(2자리)]` | `WH01-HIGH-R-01` |
| 재고 식별키 | 하나의 재고 행(Row)을 특정하는 논리적 규격 | `Product + Lot + Section + InventoryStatusSet` | DB Unique Index 처리 (6컬럼 복합 UK) |

> **섹션 코드 유효성 검증 패턴**: `^WH\d{2}-(DOCK|HIGH|MID|LOW|QUAR)-[RC]-\d{2}$`

### 2.2. 로트(LOT) 번호 생성 및 추적 규칙

#### 2.2.1. 로트 번호 정의

- 동일한 원료, 공정, 시기에 생산된 제품군을 식별하는 고유 번호
- 화장품의 품질 이력 추적 및 긴급 회수(리콜)의 최소 단위

#### 2.2.2. 번호 생성 규칙

구조: `[PRD(3)] - [YYMMDD(6)] - [VV(2)] - [SSSS(4)]`

- `PRD`: 제품 카테고리 코드 (예: SKN — 스킨케어)
- `YYMMDD`: 제조 연월일
- `VV`: 제조 공장 코드
- `SSSS`: 생산 일련번호

예시: `SKN-260507-01-0024`

#### 2.2.3. 입고 및 할당 규칙

- 하나의 입고 코드(`Inbound_ID`)에는 하나의 로트 번호를 부여하여 혼선 방지
- 동일 SKU라도 유통기한이나 제조일자가 다를 경우 별개의 로트로 분리하여 `Inventory` 테이블에 등록
- 출고 시 유통기한이 가장 임박한 로트부터 우선 할당 (FEFO)

#### 2.2.4. 추적 및 통제 규칙

- 총괄 관리자가 특정 로트를 리콜 대상으로 지정 → 해당 로트의 모든 재고 품질 상태 즉시 `HOLD` 변경
- 특정 로트에 품질 결함 발견 시 해당 로트가 배송된 모든 점포 목록과 현재 창고 내 가용 재고 위치 추출

## 3. 독립적 재고 상태 차원 및 정합성 검증

### 3.1. 3대 상태 차원 정의

#### 3.1.1. 재고 할당 상태 (AllocStatus)

| 코드값 (Enum) | 설명 | 비고 |
|--------------|------|------|
| `UNALLOCATED` | 미할당 | 출고(발주)에 사용 가능한 상태 |
| `ALLOCATED` | 할당됨 | 특정 발주 건에 묶여 출고 대기 중인 상태 |
| `SHIPPED` | 출고 완료 | 창고를 떠나 가맹점으로 배송된 상태 |

#### 3.1.2. 재고 품질 상태 (QualityStatus)

| 코드값 (Enum) | 설명 | 비고 |
|--------------|------|------|
| `NORMAL` | 정상 | 판매 및 사용 가능 |
| `INSPECTING` | 검수 대기/중 | 반품 회수 후 또는 입고 시 품질 확인 중 |
| `HOLD` | 출고 금지 | 리콜 대상이거나 품질에 문제가 발생한 상태 |
| `DISCARD_SCHEDULED` | 폐기 예정 | 검수 결과 불량으로 판정되어 폐기 대기 중 |

#### 3.1.3. 재고 위치 상태 (LocStatus)

| 코드값 (Enum) | 설명 | 비고 |
|--------------|------|------|
| `STORED` | 보관 중 | 창고 내 정상 보관 상태 |
| `MOVING` | 이동 중 | 창고 간 재고 이동 진행 중인 상태 |

### 3.2. 상태 조합 허용 및 차단 매트릭스

| 할당 상태 | 품질 상태 | 위치 상태 | 유효 여부 | 해석 |
|----------|----------|----------|----------|------|
| `UNALLOCATED` | `NORMAL` | `STORED` | 🟢 유효 | 정상 재고 |
| `UNALLOCATED` | `NORMAL` | `MOVING` | 🟢 유효 | 정상 재고를 타 창고로 이동 |
| `UNALLOCATED` | `INSPECTING` | `STORED` | 🟢 유효 | 반품 또는 입고 직후 검수 중 |
| `UNALLOCATED` | `INSPECTING` | `MOVING` | ❌ 불가 | 검수 미완료 재고 이동 불가 |
| `UNALLOCATED` | `HOLD` | `STORED` | 🟢 유효 | 보관 중 재고에 출고 제한 |
| `UNALLOCATED` | `HOLD` | `MOVING` | ❌ 불가 | 출고 금지 재고 이동 불가 |
| `UNALLOCATED` | `DISCARD_SCHEDULED` | `STORED` | 🟢 유효 | 격리 구역 대기 |
| `UNALLOCATED` | `DISCARD_SCHEDULED` | `MOVING` | ❌ 불가 | 폐기 예정 재고 이동 불가 |
| `ALLOCATED` | `NORMAL` | `STORED` | 🟢 유효 | 주문에 묶여 출고 대기 중 |
| `ALLOCATED` | `NORMAL` | `MOVING` | ❌ 불가 | 할당된 재고 타 창고 이동 불가 |
| `ALLOCATED` | `INSPECTING` | `STORED` | ❌ 불가 | 검수 중 재고 주문 할당 불가 |
| `ALLOCATED` | `INSPECTING` | `MOVING` | ❌ 불가 | |
| `ALLOCATED` | `HOLD` | `STORED` | ❌ 불가 | 결함 재고 할당 불가 |
| `ALLOCATED` | `HOLD` | `MOVING` | ❌ 불가 | |
| `ALLOCATED` | `DISCARD_SCHEDULED` | `STORED` | ❌ 불가 | 폐기 예정 재고 할당 불가 |
| `ALLOCATED` | `DISCARD_SCHEDULED` | `MOVING` | ❌ 불가 | |
| `SHIPPED` | `NORMAL` | `STORED` | 🟢 유효 | 출고 완료 처리된 상태 |
| `SHIPPED` | 그 외 모든 조합 | — | ❌ 불가 | 출고 완료 재고에 품질/이동 상태 변경 불가 |

### 3.3. 핵심 정합성 검증 로직

구현체(`InventoryStatusSet.validateStatusCombination()`)는 아래 3가지 규칙으로 위 매트릭스를 실현한다:

1. **Rule 1 — 비정상 품질 재고 할당 차단**: `allocStatus != UNALLOCATED && qualityStatus != NORMAL` → 불가
2. **Rule 2 — 이동 중 할당/출고 차단**: `locStatus == MOVING && allocStatus != UNALLOCATED` → 불가
3. **Rule 3 — 이동 중 비정상 품질 차단**: `locStatus == MOVING && qualityStatus != NORMAL` → 불가

추가 비즈니스 정합성 규칙:

- 품질 상태가 `NORMAL`이 아닌 재고는 가용 수량(`available_quantity`) 집계에서 즉시 제외
- 품질 상태가 `HOLD`로 변경될 때 이미 `ALLOCATED`인 재고가 있으면 해당 주문 할당 강제 취소 + 관리자 알림
- `MOVING` 재고는 도착지 창고에서 `STORED`로 업데이트되기 전까지 할당 불가
- `SHIPPED` 전환 시 `Inventory` 레코드 영구 삭제, `InventoryTransaction`에 최종 스냅샷 기록
- 배치 스캔(매일 00시)으로 유통기한 만료 감지 → 품질 상태 `DISCARD_SCHEDULED` 강제 전환, 모든 할당 해제
- 모든 상태 변경은 단일 트랜잭션으로 수행, 검증 실패 시 전체 롤백
- 모든 상태 전이는 `(시간, 주체, 이전 상태, 이후 상태, 사유)`를 `InventoryTransaction`에 기록

## 5. 주문 및 창고 배정 알고리즘

### 5.1. 주문 및 재고 할당 정책

**부분 할당 정책**: 발주 상품 중 재고가 부족한 상품은 발주 불가. 가용 재고가 충분한 상품만 발주 가능. 부족 상품은 창고 관리자가 본사에 입고 요청.

#### 5.1.1. 발주 상태 (OrderStatus)

| 코드값 (Enum) | 설명 | 비고 |
|--------------|------|------|
| `PENDING` | 발주 대기 | 점주가 발주서 등록을 완료한 최초 상태 |
| `IN_PROGRESS` | 작업 중 | 창고 관리자가 발주 전표 접수 후 출고 작업 시작 |
| `SHIPPED` | 배송 중 | 피킹·패킹·출고 검수 완료 후 출고된 상태 |
| `DELIVERED` | 배송 완료 | 점주가 실물 확인 후 인수한 최종 상태 |
| `CANCELED` | 발주 취소 | 점주 또는 본사 관리자 요청으로 주문 무효화 |

```
[정상 흐름]
PENDING → IN_PROGRESS → SHIPPED → DELIVERED
   │
   └──[취소]──> CANCELED
```

### 5.2. 창고 배정 알고리즘

**1단계 — 후보군 필터링**
- 점포 반경 100km 이내 창고만 추출
- 발주 SKU 목록 중 최소 1개 이상 정상(NORMAL) + 가용(AVAILABLE) 재고 보유 창고

**2단계 — 가중치 기반 통합 점수 산정**

$$S_{total} = (W_d \times S_{dist}) + (W_f \times \sum S_{fefo\_i}) + (W_{fill} \times S_{fill})$$

| 점수 | 산출 방식 |
|------|----------|
| $S_{dist}$ (주행 거리) | 외부 Routing API로 실제 주행 거리 획득 후 $S_{dist} = 100 - d$ |
| $\sum S_{fefo\_i}$ (FEFO 합산) | SKU별 유통기한 6개월 미만 재고 비중 합산 |
| $S_{fill}$ (재고 충족) | 보유 SKU 종류 수 / 발주 SKU 총 종류 수 |

**3단계 — 최종 배정**
- $S_{total}$ 최고 창고 배정
- 특정 SKU 재고 부족 시 점주에게 알림 발송
- 점주 선택(부족분 제외 발주 등)에 따라 주문 데이터 최종 업데이트

## 6. 입·출고 관리

### 6.1. 입고 관리 (Inbound)

#### 6.1.1. 입고 상태 (InboundStatus)

| 코드값 (Enum) | 설명 | 비고 |
|--------------|------|------|
| `SCHEDULED` | 입고 예정 | 본사에서 입고 전표 등록, 실물 미도착 |
| `IN_PROGRESS` | 입고 진행 중 | 물품 도착, 개별 품목 검수 작업 시작 |
| `COMPLETED` | 입고 완료 | 전 품목 검수·적재 완료, 가용 재고로 전환 |
| `CANCELED` | 입고 취소 | 계획 변경 또는 시스템 오류로 전표 취소 |

#### 6.1.2. 입고 상세 검수 상태 (InspectionStatus)

`InboundItem` 단위로 품질을 확인하는 세부 진행 상태.

| 코드값 (Enum) | 설명 | 비고 |
|--------------|------|------|
| `WAITING` | 검수 대기 | 물품 도착 후 검수 대기 중 (DOCKING 구역 위치) |
| `INSPECTING` | 검수 중 | 창고 관리자가 제조일자·유통기한·외관 파손 여부 확인 중 |
| `NORMAL` | 검수 완료(정상) | 품질 이상 없음, 정상 물류 흐름 가능 |
| `HOLD` | 검수 보류 | 파손·누락·유통기한 임박 등 불량 발견. 재고 품질 상태 `HOLD`로 전환 |

### 6.2. 출고 관리 (Outbound)

#### 6.2.1. 출고 상태 (OutboundStatus)

| 코드값 (Enum) | 설명 | 비고 |
|--------------|------|------|
| `PENDING` | 출고 대기 | 발주 주문 접수 후 출고 작업 시작 전 |
| `PICKING` | 피킹 중 | 창고 관리자가 실물 피킹 진행 중 |
| `SHIPPED` | 출고 완료(배송 중) | 피킹·패킹·검수 완료 후 배송 중 |
| `CANCELED` | 출고 취소 | 주문 취소 또는 시스템 오류로 작업 무효화 |

```
[정상 흐름]
PENDING → PICKING → SHIPPED
   │
   └──[취소]──> CANCELED
```

## 7. 리스크 및 예외 관리

### 7.1. 유통기한 단계별 모니터링 및 알림 정책

배치 스캔: 매일 00시에 전체 재고 유통기한 스캔 후 잔여일수 계산

| 단계 | 기준 시점 | 시스템 대응 |
|------|----------|------------|
| 주의 | 6개월 전 | 본사 알림 전송. 해당 로트 '프로모션/할인 판매' 권고 |
| 경고 | 3개월 전 | 창고·점주 알림. 시스템 내 FEFO 가중치 최고점 부여 |
| 만료 임박 | 1개월 전 | 창고·점주 알림 발송 |
| 만료 | D-Day | 품질 상태 `DISCARD_SCHEDULED` 자동 전환, 전체 할당 즉시 해제 |

### 7.2. 긴급 회수(리콜) 발생 시 로트 단위 통제

- 총괄 관리자가 특정 로트 지정 → 전 창고·매장 해당 로트 품질 상태 `HOLD` 일괄 변경
- 피킹·패킹 대기 중 주문이라도 해당 로트 포함 시 출고 승인 차단
- 매장 보관 재고 보유 점주에게 긴급 회수 지시 및 반품 프로세스 가이드 자동 발송

### 7.3. 폐기 처리 및 실물 삭제

- `DISCARD_SCHEDULED` 재고는 가용 수량에서 완전 제외, 물리적으로 QUARANTINE 구역으로 이동
- 실물 폐기 완료 후 관리자 승인 → DB에서 해당 레코드 삭제 + 폐기 증빙 로그 기록

## 8. 도메인별 추가 코드 정의

### 8.1. 로트 상태 (LotStatus)

로트 단위 생애주기 상태. 리콜·폐기 등 품질 이벤트 발생 시 해당 로트의 모든 재고에 일괄 적용.

| 코드값 (Enum) | 설명 |
|--------------|------|
| `AVAILABLE` | 정상(가용) — 출고 및 배분 가능 |
| `HOLD` | 보류 — 품질 이슈로 출고 보류 |
| `EXPIRED` | 유통기한 만료 — 사용 불가 |
| `RECALLED` | 리콜 대상 — 즉시 출고 금지 |
| `DAMAGED` | 파손 — 물리적 파손 확인 |
| `DISPOSED` | 폐기 — 실물 폐기 처리 완료된 최종 상태 |

### 8.2. 품질 검사 결과 (InspectionResult)

`QualityInspection` 엔티티에서 사용. `InspectionStatus`(입고 상세 진행 상태)와 별개로 검사관의 최종 판정을 기록.

| 코드값 (Enum) | 설명 |
|--------------|------|
| `PASSED` | 합격 — 품질 이상 없음. 재고 품질 상태 `NORMAL` 유지 |
| `FAILED` | 불합격 — 결함 확인. 재고 품질 상태 `HOLD` 전환 트리거 |

### 8.3. 재고 거래 유형 (TransactionType)

`InventoryTransaction` 테이블에서 재고의 모든 상태 전이와 수량 변동 추적에 사용. `reference_id` 필수 여부로 외부 문서 연결 필요성을 구분.

| 코드값 (Enum) | 설명 | reference_id 필수 |
|--------------|------|:-----------------:|
| `INBOUND_PUTAWAY` | 입고 실물 적재 | ✓ |
| `INBOUND_CANCEL` | 입고 적재 취소 | ✓ |
| `ALLOCATE` | 출고 가용재고 할당 | ✓ |
| `UNALLOCATE` | 출고 할당 취소 | ✓ |
| `PICKING` | 출고 실물 피킹 | ✓ |
| `SHIP` | 최종 출고 완료(소멸) | ✓ |
| `LOCATION_MOVE` | 창고 내 위치 이동 | — |
| `QUALITY_INSPECTING` | 품질 검사 착수 | — |
| `QUALITY_HOLD` | 품질 결함 보류(HOLD) | — |
| `QUALITY_RELEASE` | 품질 정상 복구(NORMAL) | — |
| `DISCARD` | 실물 폐기 처리 | — |
| `SPLIT_DEDUCT` | 재고 분할 — 원본 수량 차감 | — |

### 8.4. 협력사 유형 (PartnerType)
