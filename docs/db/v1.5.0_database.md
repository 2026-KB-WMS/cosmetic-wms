# 데이터베이스 설계서 v1.5.0

> 최종 업데이트: 2026-07-07  
> 이전 버전: v1.4.0 (2026-06-20)  
> 기준: `src/main/resources/db/migration/V1__init_schema.sql`, `V2__add_foreign_keys.sql` (Flyway)

---

## 1. 개요

- **목적**: WMS 프로젝트의 데이터 정합성을 유지하고, 화장품 도메인 특수성(유통기한, 리콜)을 반영한 물리 데이터 구조를 정의함
- 본 버전부터 실제 Flyway 마이그레이션 스크립트를 단일 진실 공급원(Source of Truth)으로 삼아 명세를 동기화함

---

## 2. 엔티티 그룹

- **사용자 및 조직**: `member`, `store`, `warehouse`, `section`, `partner`
- **상품**: `product`(+ ProductInfo 내장), `category`, `product_type`
- **재고 및 로트**: `inventory`, `inventory_transaction`, `lot`
- **입고 관리**: `inbound`, `inbound_line`, `quality_inspection`
- **출고 관리**: `orders`, `orders_item`, `outbound`, `outbound_item`
- **이벤트 실패 보상**: `failed_inspection_event`, `failed_assignment_event`
- **미구현(설계 보류)**: `member_store`, `member_warehouse`, `stock_transfer`, `stock_transfer_item`, `return`, `return_item`, `recall`, `disposal`, `disposal_item` → 5장 참고

---

## 3. 공통 컬럼

모든 테이블에 공통으로 포함되는 감사(Audit) 컬럼 (`BaseEntity` + JPA Auditing):

| 컬럼명 | 타입 | 설명 |
|--------|------|------|
| `created_by` | BIGINT NOT NULL | 최초 등록자 ID |
| `created_at` | DATETIME(6) NOT NULL | 최초 등록 일시 |
| `updated_by` | BIGINT | 최종 수정자 ID |
| `updated_at` | DATETIME(6) | 최종 수정 일시 |

> **예외**: `outbound_item` 테이블은 Audit 컬럼을 포함하지 않음

### [T-09] lot

- 로트 번호는 `YYMMDD-{입고ID}-{제조사 로트 번호}` 복합 포맷을 애플리케이션 레벨에서 조합 (별도 저장 컬럼 없음, 2026-06-29 정책 변경)
- `inbound_id`는 순환 참조 방지를 위해 FK 제약 없이 논리적 참조만 유지

```sql
CREATE TABLE lot (
    lot_id              BIGINT      NOT NULL AUTO_INCREMENT,
    inbound_id          BIGINT      NOT NULL,
    manufacturer_lot_no VARCHAR(50) NOT NULL,
    manufacturing_date  DATETIME(6) NOT NULL,
    expiration_date     DATETIME(6) NOT NULL,
    status              VARCHAR(20) NOT NULL,
    product_id          BIGINT      NOT NULL,
    created_by          BIGINT      NOT NULL,
    created_at          DATETIME(6) NOT NULL,
    updated_by          BIGINT,
    updated_at          DATETIME(6),
    PRIMARY KEY (lot_id),
    CONSTRAINT uq_lot_inbound_manufacturer UNIQUE (inbound_id, manufacturer_lot_no),
    CONSTRAINT chk_lot_date                CHECK  (manufacturing_date <= expiration_date)
);

ALTER TABLE lot
    ADD CONSTRAINT fk_lot_product
        FOREIGN KEY (product_id) REFERENCES product (product_id);
```

### [T-14] quality_inspection

- Polymorphic Association(`source_type` + `source_id`)으로 입고 외 다른 도메인의 검사 요청도 처리 가능
- 검사 대상을 직접 식별하는 `product_id`, `lot_id`, `warehouse_id` FK 보유 (기존 `inventory_id` FK 제거)

```sql

    product_id          BIGINT      NOT NULL,
    lot_id              BIGINT      NOT NULL,
    warehouse_id        BIGINT      NOT NULL,
    inspector_id        BIGINT,
    status              VARCHAR(20) NOT NULL,
    inspection_quantity INT         NOT NULL,
    passed_quantity     INT         NOT NULL,
    failed_quantity     INT         NOT NULL,
    defect_reason       VARCHAR(100),
    expiry_date         DATE,
    created_by          BIGINT      NOT NULL,
    created_at          DATETIME(6) NOT NULL,
    updated_by          BIGINT,
    updated_at          DATETIME(6),
    PRIMARY KEY (inspection_id)
);

ALTER TABLE quality_inspection

ALTER TABLE quality_inspection
```

## 5. 폐기 및 보류된 설계

### 5.1 폐기된 테이블

- **`sku_sequence`**: ADR "SKU 코드 포맷 단순화"(2026-06-24)에 따라 폐기. SKU 코드는 Product PK 기반 `P%06d` 포맷으로 생성.

### 5.2 미구현 테이블 (설계 보류)
