# 데이터베이스 설계서 v1.4.0

> 최종 업데이트: 2026-06-20  
> 이전 버전: v1.3.0 (2026-06-20)

---

## 1. 개요

- **목적**: WMS 프로젝트의 데이터 정합성을 유지하고, 화장품 도메인 특수성(유통기한, 리콜)을 반영한 물리 데이터 구조를 정의함

---

## 2. 엔티티 그룹

- **사용자 및 조직**: `member`, `store`, `warehouse`, `section`, `partner`, `member_store`, `member_warehouse`
- **상품**: `product`, `category`, `product_type`, `sku_sequence`
- **재고 및 로트**: `inventory`, `inventory_transaction`, `lot`
- **입고 관리**: `inbound`, `inbound_item`, `quality_inspection`
- **출고 관리**: `orders`, `order_item`, `outbound`, `outbound_item`
- **창고 작업**: `stock_transfer`, `stock_transfer_item`
- **품질 및 사후 관리**: `recall`, `disposal`, `disposal_item`, `return`, `return_item`

---

## 3. 공통 컬럼

모든 테이블에 공통으로 포함되는 감사(Audit) 컬럼:

| 컬럼명 | 타입 | 설명 |
|--------|------|------|
| `created_by` | BIGINT NOT NULL | 최초 등록자 ID |
| `created_at` | DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP | 최초 등록 일시 |
| `updated_by` | BIGINT | 최종 수정자 ID |
| `updated_at` | DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | 최종 수정 일시 |

### [T-16] quality_inspection

> **[변경 v1.3.0]** Polymorphic Association 패턴 도입으로 구조 재설계  
> **[변경 v1.4.0]** 수량 기반 검사 결과 추적 컬럼 추가 및 CHECK 제약조건 강화

| 컬럼명 | 한글명 | 타입 | 제약조건 | 설명 |
|--------|--------|------|----------|------|
| `inspection_id` | 검사 ID | BIGINT | PK, AI | 품질 검사 고유 번호 |
| `inventory_id` | 재고 ID | BIGINT | FK | 검사 대상 재고 참조 (검사 시점에 미확정 시 null) |
| `source_id` | 출처 도메인 ID | BIGINT | NOT NULL | 출처 도메인의 PK ID |
| `source_type` | 검사 요청 출처 | VARCHAR(20) | NOT NULL | 어떤 도메인에서 요청했는지 구분 (`INBOUND` 등) |
| `inspector_id` | 품질 검사관 ID | BIGINT | FK | 검사 수행 담당자 (미배정 시 null) |
| `status` | 진행 상태 | VARCHAR(20) | NOT NULL | `READY`, `IN_PROGRESS`, `COMPLETED` |
| `defect_reason` | 불량 사유 | VARCHAR(100) | | 파손, 누액, 변색 등 (`failed_quantity > 0` 시 필수) |
| `inspection_quantity` | 검사 대상 수량 | INT | NOT NULL | 검사를 수행할 총 수량 |
| `passed_quantity` | 합격 수량 | INT | NOT NULL DEFAULT 0 | 검사 통과 수량 |
| `failed_quantity` | 불합격 수량 | INT | NOT NULL DEFAULT 0 | 검사 불합격 수량 |

**v1.3.0 대비 변경사항:**
- `result VARCHAR(20)` → **제거** (합격/불합격을 `passed_quantity` / `failed_quantity`로 수량 단위 추적하도록 대체)
- `inspector_id BIGINT` → **복구** (NOT NULL → **nullable** FK로 재추가, 미배정 허용)
- `defect_reason VARCHAR(50)` → `defect_reason VARCHAR(100)` — 사유 길이 **확장**
- `inspection_quantity INT NOT NULL` → **신규** — 검사 대상 총 수량
- `passed_quantity INT NOT NULL DEFAULT 0` → **신규** — 합격 수량
- `failed_quantity INT NOT NULL DEFAULT 0` → **신규** — 불합격 수량
- `chk_quality_inspection_qty_positive` CHECK → **신규** — 수량 양수 보장
- `chk_quality_inspection_qty_balance` CHECK → **신규** — COMPLETED 상태 시 합/불합격 수량 합계 = 검사 수량 강제
- `chk_quality_inspection_defect_reason` CHECK → **신규** — 불합격 수량 > 0 이면 불량 사유 필수
- `fk_quality_inspection_member` FK → **신규** (`inspector_id` → `member`)
- COMMENT: `'입고 품질 검사 기록 테이블'` → `'품질 검사 수행 및 기록 테이블'`

```sql
CREATE TABLE quality_inspection (
    inspection_id      BIGINT NOT NULL AUTO_INCREMENT,
    inventory_id       BIGINT,
    source_id          BIGINT NOT NULL,
    source_type        VARCHAR(20) NOT NULL,
    inspector_id       BIGINT,
    status             VARCHAR(20) NOT NULL,
    defect_reason      VARCHAR(100),
    inspection_quantity INT NOT NULL,
    passed_quantity    INT NOT NULL DEFAULT 0,
    failed_quantity    INT NOT NULL DEFAULT 0,

    created_by BIGINT NOT NULL,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_by BIGINT,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    PRIMARY KEY (inspection_id),

    CONSTRAINT chk_quality_inspection_qty_positive
        CHECK (inspection_quantity > 0
            AND passed_quantity >= 0
            AND failed_quantity >= 0),

    CONSTRAINT chk_quality_inspection_qty_balance
        CHECK (status <> 'COMPLETED'
            OR (passed_quantity + failed_quantity = inspection_quantity)),

    CONSTRAINT chk_quality_inspection_defect_reason
        CHECK (failed_quantity = 0
            OR (defect_reason IS NOT NULL AND TRIM(defect_reason) <> ''))
) COMMENT='품질 검사 수행 및 기록 테이블';

ALTER TABLE quality_inspection
    ADD CONSTRAINT fk_quality_inspection_inventory
        FOREIGN KEY (inventory_id)
        REFERENCES inventory (inventory_id);

ALTER TABLE quality_inspection
    ADD CONSTRAINT fk_quality_inspection_member
        FOREIGN KEY (inspector_id)
        REFERENCES member (member_id);
```
